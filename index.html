从 CNN、大规模自监督视觉（Scaled SSL）、EasyPhoto、Valley2，到 Streaming Video Agent，我逐渐意识到：真正的工作突破，既在 encoder，更在 output。

2015–2018 · Inductive bias 是工程判断

2015 至 2018：从转码到一场反潮流的胜利

回顾大学时光，对我人生影响最大的，可能是浙江大学电子信息工程专业的一次暑期企业参观。（不知道现在学校还有没有这个环节，但我的建议是取消掉。）那次参观回来，我就坚定了转码的决心。即使当时已经选择了某位“名”满天下的电信泰斗做导师，也进组做了一些项目，我还是决定换一条路。

除了这位老师过于“有名”，师兄又极力劝退我，还有一个原因：电路系统里的很多研究，已经到了实验误差、noise 和真正的研究进展很难区分的程度。这对喜欢确定性工作的我来说很痛苦。（视觉世界后来的发展，使得这句话回看起来格外讽刺。）

一番调研后，我想找蔡登老师做机器学习，于是联系了他。他很支持，给了我一些论文自学，我也去上了他的课。十年过去，其他细节都已经模糊，课堂上讲的 AdaBoost 却一直没有忘。

到了大四保研时，我阴差阳错进了一个做嵌入式视觉的团队。果然，人生重大的变化往往无法准备周全。于是我很早就开始折腾 NVIDIA 开发板，用 CUDA 和 C++ 写视觉算法。那时 CNN 大热，我也自学了不少课程。比起电路板世界里的误差和波动，当时计算机视觉——还是手工特征的年代——显得确定得让人羡慕。后来证明，这个领域的“炼丹”程度比电路世界夸张得多。

大四和研一，我一直在做实验室的嵌入式视觉项目。其间参加过一次手势识别比赛。我选了一圈，最后用了 Viola-Jones。实在是因为这个任务 too damn easy, Haar feature is enough。

ARM 当时似乎想推自己的 Mali GPU 配套，但在我使用的驱动和开发栈里，实际用下来确实很烂，导致 CNN 方案很难在那块板子上发挥性能。反过来，RK3399 有四个 Cortex-A53 小核和两个 Cortex-A72 大核，自己写 C++ / OpenCV 的 Viola-Jones 很好调度。那套实现默认吃满六个 CPU 核，在我的测试里反而最好用。

那时我对嵌入式视觉项目的开发已经得心应手。我喊了很多人采集数据，还提前一天去赛场测试环境光照，做最后的适配。据我对现场的回忆，当天我就觉得自己稳赢了：其他人的 YOLO 只能跑到 1 至 5 FPS，我的纯推理吞吐接近 100 FPS，快到采集、拷贝和显示成了瓶颈；完整的 480p 摄像链路实际只能跑到约 25 FPS。

最后不出意外，我们在所有赛道都爆杀了其他人。讲道理，应该给我发三份一等奖，但主办方还是把其他赛道的几万块奖金发给了别人。毕竟重在参与。

这段经历对我后来怎么理解 Vision 很重要。毕竟我的世界是从 pixel 搭起来的，第一个算法就是手写 ISP，用 CUDA 去噪。视觉算法很抽象，infra 却具体得过分：每一个字节怎样在内存里组合，怎样 gate，怎样 reshape，都得先在我脑子里过一遍。这个东西给人一种安全感。

所以今天我会用 inductive bias 来概括这种判断。这个词是后来补上的；当时的我想得没有这么理论。output 要什么，硬件能跑什么，我应该把什么结构塞进系统——大概就是这些。

资料核对：inductive bias 与比赛公开记录

Mitchell 在 1980 年的《The Need for Biases in Learning Generalizations》中给出了机器学习领域常引用的早期定义。本文不声称他首次创造了这个词，也不把我记得 AdaBoost 与后来自称“统计学派”写成因果关系。

这里的 inductive bias 指学习系统在有限数据之外，已经通过结构、假设或搜索空间带进去的偏好。对 CNN 来说，locality 和 weight sharing 是结构性先验；对这场比赛来说，任务、硬件和数据共同决定了我愿意把什么假设写进系统。它不是“用了旧算法”的同义词，也不是训练后学到的卷积核本身。

公开仓库记录：系统运行在 Rockchip RK3399 和 Ubuntu 16.04 上，以 C++ 和 OpenCV 的 Viola-Jones cascade 完成五类手势的定位与分类，并保留 CaffeOnACL / CNN 接口。仓库所称比赛版本在距离 1 至 1.5 米、frame_control=3、use_cnn=0 时，单手势自测为 2.2 至 4.9 ms，多手势样例为 3.8 至 10.3 ms。这些记录能证明公开实现及仓库自测，不能单独证明比赛名次或其他选手的现场表现；后者是我的亲历回忆。

Momenta · 规模第一次改变

研二，Momenta：第一次把规模当成方法

不过，当时还在学校里瞎折腾的我肯定想不到，一两年后竟然能和那些已经名声大噪的大牛一起工作。

研二时，我去 Momenta 打工，认识了 Jie Hu 和 Shaoqing Ren，也开始做更正统的 CNN 结构研究。在我心里，Shaoqing Ren 是 2015 到 2020 年间目标检测领域的绝对高山；Jie Hu 则是 Vision Transformer 到来以前，CNN 识别网络结构最后的余晖。我一直觉得，他们是那个黄金白银时代最璀璨的明珠。

时代背景：Faster R-CNN 与 SE-Net

Jie Hu 对我特别好，也是非常 hands-on 的选手。我们花了很多时间用 Caffe 做 Scaling Face ID。基于表征学习的人脸识别真的很吃结构和数据，目标又足够清楚，做起来非常开心。国内丰富的数据，也使这里成为当时很适合做大规模人脸表征的地方。

DP、TP 这些名字，其实是后来读刘铁岩老师的书才真正弄明白的。但在那之前，我已经在 Caffe 里写 kernel、写通信，按类别切 FC / Softmax，硬把超大类别的人脸分类跑起来了。看着 scale 真的换来性能，那种感觉非常激动。

我当时几乎把 scaling class 看成表征学习唯一的方案。这大概是我心里最早的一条 scaling law，只是当时还没有这个名字。这个想法后来影响了我很长时间。

那也是我第一次在工作中接触上百张卡的分布式训练，做超大规模人脸分类、表征学习和剪枝。规模突然变了，核心问题仍然清楚：怎样学到更好的表征，怎样让结构、计算与任务互相匹配。那时的一些算法改进，也确实带着数学上的美感。

论文与口述的边界：公开实验不是全部工作规模

我的硕士论文记录了单卡、单机 8 卡和多机 32 卡实验，也记录了大规模人脸分类、度量学习与混合并行。上百卡和剪枝来自我的工作回忆，不能由论文单独证明；论文也没有使用 scaling law 这个说法。

当时按类别切分 FC / Softmax 可以归到 model parallelism，与今天 tensor parallelism 的一部分思想相通，但不是 Transformer 里常说的同一套实现。

正文里的“唯一方案”和“最早的 scaling law”是在记录我当时的判断，不表示它们是今天严格成立的技术结论，更不等于我已经发现了 foundation-model scaling。

Problem 01 · Output interface

当时的 Vision 为什么清晰：答案几乎都写好了

在 2021 年以前，我其实很少问 Computer Vision 的 long vision 是什么，因为眼前的事太清楚了。那时数据和算力都受限，业界真正能解决、又有产业价值的问题就那么多。识别大多就是分类或检索，检测大量围着特征、类别和坐标转，OCR 再复杂，也可以写成一段有限序列。output 一旦明确，后面该干什么几乎都顺着长出来了。

我那时会很自然地把自己归到“统计学派”。拿到一个任务，我先看 output 要什么，硬件能给什么，然后才是输入、结构、数据和计算应该怎么配。先把问题定义到能做、能测、能交付，这套方法在当时就是很好用。

说得直接一点，那时整个行业都像在拿着锤子找钉子。摄像头往城市、车和每个人的口袋里铺，算力也开始被塞进视觉数据流，low-hanging fruit 偏偏又真的到处都是。大家一拥而上，用结构化输出去填现实社会的需求。

这套系统也给大部分人安排好了位置。有人做框架，有人做结构，有人做算法。表面分工不同，底层都在做同一件事：

找到可以形式化输出的场合，把算力适配进数据流。

任务先给出固定的输出接口，系统再把输入稳定、高效地变成这个输出。真正的工作突破既可能发生在 encoder，也可能发生在 output；只是当时 output 往往早已由问题定义者写好，于是研究的注意力自然集中到前者。

后来我才把这团疑云叫作第一个问题：输出的问题。结构化输出当然有价值，可它也会反过来决定整个领域能看见什么。现实一旦无法压成一个类别、一个向量、几个坐标或一段有限序列，原来的系统就很难接住。

2020–2021 · Nothing interesting

2020 至 2021：CV = dead game

后来 Jie Hu 和 Shaoqing Ren 都离开了。我一个人流落到 Aliyun-PAI，作为阿里集团的中台支持不同业务的视觉算法。

那几年，我和 Jie Hu 以及其他稍微资深一些的同行聊天，大家经常表达同一种厌倦。小一点的问题，随便搞几百张、上千张数据，找个 pretrained model，finetune 一把——本质上就是修一下 output shape——凑合凑合就够用了。nothing interesting。EasyCV 最早差不多也是把 metric learning、分类框架和 SSL pretrain 组合了一下，因为我发现这就足够集团大部分人用了，顺便再接一点简单好用的目标检测器。

空气里有一种很强的情绪：CV = dead game。

我当时的抱怨其实很粗暴：把 AdaBoost、Viola-Jones、SIFT 和 CNN 放在同一条线上看，有什么区别呢？过去是针对特定问题手工 design encoder，后来是有了 BP，再结合 Vision 的 locality，从数据里优化出 conv kernel as encoder。encoder 的产生方式变了，最后做的还是分类、回归或检索。看不出任何智能。

后来再看：机制当然不是一回事

上面记录的是我当时的不满足，不是说这些方法在表征机制上没有实质差异。BP 让系统能从数据中学习特征，CNN 又把 locality 与 weight sharing 写进结构，自动化程度已经发生了巨大变化。我真正不满足的是：当输出与评测方式不变时，我仍然看不出这种系统怎样走向自己理解的“智能”。

Encoder 统一了，问题没有

2020 至 2021：MoCo、SwAV 与 unified encoder

大约在 2020 至 2021 年，Kaiming He 的 MoCo 系列让大家在精神上稍微放松了一点。大家开始从 task-specific encoder 转向 SSL，寻找一种不依赖人工类别标签的 unified encoder。看起来 Kaiming 又一次引领了时代。

MoCo 最让我兴奋的，不只是 queue 或 momentum encoder，而是它真的让大家开始相信：也许不用围着每一个 task 单独做 encoder 了。SwAV 又用 swapped assignment 往前走了一步。同一张图的不同视图要保持实例一致，或者落到一致的在线聚类原型；这些是不同的学习信号，不能和人脸身份标签简单说成同一种“class”。

相比早两年围绕 softmax、CircleLoss 做大规模 Face ID，这一步确实把表征学习的边界放宽了。放到阿里内部，它也真的能换来指标和迁移收益。

可我当时，甚至后来很长时间，都觉得这条路挺失败。encoder 越来越 general，旧流程也越来越顺，可 output 和 reward 没有被重写，观察方式也仍由人规定。我想找的东西不在这里。

“失败”说的是哪一层

这不是说 MoCo、SwAV 或后来的 DINO 系列没有价值。它们实实在在改造了训练目标，也支持图像级与像素级任务。这里的“失败”只针对我后来关心的问题：它们主要统一了表征，下游输出、评测协议和观察方式大多仍由人预先规定。

这似乎一直是 CV 人最爱干的事情：做 general systemization。OpenMMLab 的一系列框架就是最典型的例子，task、model、training 和 deployment 都可以整整齐齐地装进去。可装进去的还是原来的问题。系统越来越 general，我的疑惑却没有变少。

工程侧记：上亿数据真正难在哪里

我后来独立负责把 MoCo v2、SwAV、DINO 等自监督方案落到阿里内部多个团队。算法验证反而相对直接，真正反复折腾的是让上亿图片稳定进入多机训练：数据增强算子的效率，PyTorch DDP 在超大文件列表和多进程下的内存问题，亿级随机读取，以及跨机器 batch 的通信效率。

这些细节不证明任何新的学习理论，却让我越来越确信算法与工程系统很难分开。无论嵌入式 Vision 还是后来的大规模训练，模型能力都要落到硬件、数据与计算系统里。

PAI · 算法与 Infra

2020 至 2022，PAI：scale 带来的甜点时刻

对初入职场的我来说，这段工作仍然很 interesting。我被分配去独当一面，把 MoCo v2、SwAV、DINO 这一套 SSL 方案落到阿里内部的多个团队，框架、存储、计算、性能，各种问题一箩筐。数据规模带来真实的 infra 挑战，scale 也确实换来了指标提升。既有难题，也有收益，这是一个甜点时刻。

我还认识了一群很厉害的 Infra 大佬。当时只道是平常的兄弟，后来再看，一个个都这么有实力。和他们共事，无形中让我觉得算法和 infra 基本没法分开。不管是 Embedded Vision，还是 Scaling Law，算法最终都要在系统里兑现。

我这样做了一到两年，在表征学习和结构上积累了一些心得（做 Vision 的人真是没 Vision）。YOLOX-PAI、SMT 等公开项目里还能看到那段工作的痕迹，也能看到一种在噪音里包装更多噪音、努力证明自己有价值的影子。可到 2022 年左右，这个甜点时刻也差不多结束了。

2022–2023 · Long vision 缺席

2022 至 2023：Lost，和几次没有看懂的转向

我不是一进入 PAI 就迷茫。真正的 Lost 出现在 2022 年以后。局部问题仍然有意思，我却越来越回答不了一个更长的问题：Computer Vision 接下来究竟要去哪里？

2022 · 类别表开始松动

我错过的 Open-Vocabulary Detection

当时，一些同事和朋友已经去做 Open-Vocabulary Object Detection。我也跟着学过一点，可惜没有今天的见识，follow 得实在太少。

现在看，那一步其实已经在松 output 了：captions 和语言表示开始决定模型可以识别什么。它还不是自然语言回答，但门已经开了一条缝。我当时没有接着往下想。

术语边界：Open-Vocabulary 与 Open World

我们当时实际做的主线是 Open-Vocabulary Object Detection：用 captions 和语言表示扩展可检测类别，输出仍然主要是 box 与类别语义。对 Open World Object Detection 也有涉猎，也就是发现 unknown object，并在获得新标签后增量学习。两者不能混写。

2022 · 把智能误认成局部问题

最大的浅薄时刻：我嘲笑了自然语言操作 Excel

也是在那时，某位今天已经是大大大大佬的人在做类似 CLIP 的多模态对齐，也开始探索一些我完全无法理解的 NLP 任务。其中一个想法，是让用户用自然语言操作 Excel。

我们有过简单交流。当年的我完全没有意识到这件事的重要性，还明确表达了自己的嗤之以鼻。显然，我当时只觉得 customized output 是 Vision 的问题，没有意识到这是智能的问题。

现在回看，这恐怕是我最大的浅薄时刻。这么看，有一点语言学背景真的蛮重要的，哈哈哈哈。

时间说明：这里的 GPT 时刻指 ChatGPT 3.5 带来的第一轮冲击

这里不再把“GPT 时刻”悬置在 ChatGPT 与 GPT-4 之间。对我最早、最直接的震动来自 2022 年 11 月发布的 ChatGPT 3.5；后续冲击当然持续了数月。《朝闻道》里的场景是借用，“仰望星空时刻”不是小说原文术语。

2023 · 局部成功

2023，EasyPhoto：虚假的回光返照

GPT 时刻之后，我被狠狠地震惊，却没有把震惊变成方向。缺少高质量交流的我，完全迷失了做任何事情的动力。Vision，not interesting；infra 和 model structure，我也不再主动跟进。

同期 Diffusion 爆发。生成式输出确实让我迈出了旧判别范式，可我很快又掉回 CV 人 low-hanging fruit 的恶习：这点东西看起来离产品已经很近，似乎很快就能商业化。于是我屁颠屁颠地去做了 EasyPhoto。

老实说，我做得很开心。GitHub star 涨得很快，我每天做一点边边角角的优化，越来越像一个 PD。可我完全没有意识到，外面的世界正在发生多大的变化。

我沉浸在 PAI 这个小团队虚假的回光返照里。同一时期，一些更有见识的伙伴已经开始行动。看起来大家都在做正确的事情，而我已经彻底迷失了。

工程变量，还是能力边界

回头看：我错过的不是生成，而是 Scale Up

回头看，那段时间其实挺快乐。我已经从之前 data-driven 的垃圾理解范式转向生成问题，似乎走出了一步。可我完全 miss 掉了那个时代最大的主题，Scale Up。

这不是说我不知道规模有用。我早就在 PAI 做过上亿数据的自监督学习，也亲眼看过数据和算力怎样换来收益。那时我仍把 scale 当成既定任务里的工程变量：数据更多，训练更大，encoder 更好，指标更高。

我没有及时看见，foundation-model scale 正在改变模型的能力边界，甚至改变问题的定义。输出从判别换成生成，理解技术变化的框架却没有跟着变。EasyPhoto 本身不是失败；问题在于我把即时反馈错当成了长期方向。

不能说完全没人提醒我。有位朋友几乎见我一次就骂一次：“不要再做垃圾了，你为什么还没离开。”我却心心念念等着在阿里晋升。大望京公园还是去少了；那时如果多约几次散步，也许会早一点醒过来。

后来我才意识到，自己最大的快乐从来不是组织晋升，而是让技术从不确定走到确定，再走到落地。EasyPhoto 的快乐恰好证明了这一点：它没有替我回答 long vision，却让我重新想起自己到底喜欢做什么。

这里我要骂一句：阿里巴巴确实挺垃圾的。至少在我当时接触的圈子里，几乎每个人都在吐槽内部像个封建王朝。可另一方面，阿里那几年的工程与研究人才密度又确实是独一档。这样一个让我反复失望的组织，仍然能诞生 Qwen 这样的作品。

Valley2 · Language interface

VLM 时代：Valley2 自然语言打开输出

离开阿里以后，感谢我的良师益友 Matt Qiu 给了我一个机会去做 Valley2。

它很接近我当时心目中的 semantic output vision model。language model 已经让我们看到了一点智能，那这件事能不能推到 Vision？基于大量 vision-language data 做一轮对齐，模型终于能用自然语言理解和回答开放问题。对当时一大批 Vision 从业者，包括我，这确实像找到了一个宣泄口。

可老 CV 人换了范式，脑子没有那么快换过来。我们还是在想 better pretraining for customized problems，说白了，就是换个范式把 encoder 做得更大：ViT、桥接结构、数据清洗，再给具体任务配数据。这几乎是 CV 从业者本能的顺延。这些活当然有用，也让我慢慢有了做 multimodal model 的 taste；可 output 已经变了，我们理解问题的方式还留在原地。

术语便签：semantic output 暂时怎样写

semantic 太宽，也不是 VLM 时代公认的阶段名。正文保留我当时的说法；需要准确描述变化时，使用 language interface 或“自然语言开放输出”：回答不再被预先压成类别、坐标或有限序列。

o1 · Compositional reasoning

o1 时刻：从定制任务走向能力组合

在国内从业者迎来 R1 时刻以前，o1 已经帮我们从 customized problem 走向组合问题：感知、OCR、计算和推理可以被串起来，完成任何单一能力都覆盖不了的复杂任务。

在 o1 之后、R1 公布之前，我们已经在 Valley 上做了 LLaVA-CoT 和 DPO，也取得了不错的结果。那时我们很兴奋地发现，感知和推理虽然可以解耦地存在于模型能力中，可一旦把它们组合起来，确实能解决复杂得多的问题。

CoT 和 DPO 在方法上不同，但在我们当时的实践里是一脉相承的：我们找出有效的 reasoning pattern 或 preference，再给模型学。公开的 Valley2 方案把过程拆成 summary、caption、reasoning 和 conclusion，几乎就是我们当时理解的一个截面：能力已经在模型里，人的任务是把好用的组合枚举出来，再教给它。

时间线：公开记录不能倒推内部实验顺序

o1-preview 于 2024 年 9 月发布，Valley2 论文于 2025 年 1 月 10 日公开；DeepSeek-R1 模型于 1 月 20 日发布，论文于 1 月 22 日提交。Valley2 论文记录了 LLaVA-CoT，没有写 DPO；公开仓库到 2 月 9 日才宣布 Valley2-DPO。据我的内部经历，DPO 实验早于 1 月 20 日；2 月 9 日只是公开记录，不能倒推实验顺序。

DPO 的 preference pairs 不一定由人逐条给出，也可以来自模型、规则或合成流程。公开材料没有说明 Valley2-DPO 的具体偏好来源，所以正文只说训练流程先提供外部构造的偏好关系。
